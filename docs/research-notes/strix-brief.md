# Strix (usestrix/strix) — Implementation Brief

Evidence: `main` @ pushed 2026-09-17 (GitHub API), 507 files, Python 3.12+, ~35k LOC in `strix/` + ~23k LOC in `tests/` (95 test files), 63,243 stars, Apache-2.0. Verified against mirrored source.

## 1. Agent architecture

**Framework: OpenAI Agents SDK — no LangGraph, no custom loop.** `pyproject.toml`: `openai-agents[litellm]>=0.19.0,<0.20`, `openai>=2.45.0,<3`, `litellm>=1.101.0`, `pydantic-settings`, `docker>=7.1.0`, `cvss>=3.2`, `caido-sdk-client>=0.2.0`, `reportlab`, `pypdf`. Agents are `agents.sandbox.SandboxAgent` built by `build_strix_agent(...)` (`strix/agents/factory.py`), with SDK capabilities `Filesystem(...)` and `Shell(...)`, each given a `configure_tools` callback. (`docker_client.py` still says "Pinned to `openai-agents==0.14.6`" — stale.)

**Root and children are one class, differing in tools and prompt:** root = `_BASE_TOOLS + extras + finish_scan`; child = `_BASE_TOOLS + extras + agent_finish` (`factory.py:692-694`). `make_child_factory(...)` returns the `_factory(*, name, skills)` closure injected into run context as `spawn_child_agent`; `create_agent(name, task, inherit_context=True, skills=None)` calls it, gating skills through `validate_requested_skills(max_skills=5)` and passing `parent_history=ctx.turn_input`.

**The "graph" is a runtime registry, not a declarative graph.** `strix/core/agents.py` defines `AgentCoordinator` (per-agent `AgentRuntime`, `parent_of`, `statuses`, asyncio inboxes) and `Status = Literal["running","waiting","completed","stopped","crashed","failed","budget_paused"]`, with `send`, `wait_for_message`, `consume_pending`, `park_waiting`, `request_stop`, `cancel_descendants(_graceful)`, `graph_snapshot`, `snapshot`/`restore`, and budget state (`trigger_budget_stop`, `pause_for_budget`, `resume_from_budget_pause`).

**Termination is tool-gated.** `_finish_tool_use_behavior` (the SDK `tool_use_behavior` hook) ends a run only when a lifecycle tool returns JSON with `success` plus `agent_completed` (`agent_finish`) or `scan_completed` (`finish_scan`); `_PARKING_TOOLS = frozenset({"respond_to_user","wait_for_agents"})` park instead of ending, interactive only. `finish_scan` refuses while any child is `running`/`waiting`; `agent_finish` refuses for root.

**Coordination is message-passing into parent sessions.** `agent_finish` renders a plaintext `== Completion report from <name> (<id>) ==` block and appends the ids the child actually filed, read from `ReportState` via `_filed_reports_by` — the narrative `findings` is prose; "a parent that wants to act on a child's work needs the report ids." The prompt mandates nested trees and a 3-agent chain per vulnerability (Discovery → Validation → Reporting).

## 2. Sandbox / execution isolation

**One container per scan, shared by every agent** — not per agent. `strix/runtime/session_manager.create_or_reuse(scan_id, image, local_sources, extra_files, status_sink)` caches `_SESSION_CACHE[scan_id] = {client, session, caido_client, extra_file_staging_dir}`. Default image `ghcr.io/usestrix/strix-sandbox:1.3.0` (`STRIX_IMAGE`). `strix/runtime/backends.py` registers exactly one backend, `"docker"`.

**Host↔sandbox transport** is the SDK's `Shell` (`exec_command`, `write_stdin`) and `Filesystem` (`apply_patch`, exposed to the model as **`patch`** via `_TOOL_NAME_OVERRIDES`; plus `view_image`), bound per-run to the live `SandboxSession` (impl `agents.sandbox.capabilities.tools.shell_tool.ShellTool`). `exec_command` defaults `shell="bash"` and has no TTY unless `tty=true`; `write_stdin` requires a live PTY process. Strix clamps `max_output_tokens` to `ContextSettings.tool_output_max_tokens`.

**Files in:** local dirs land at `/workspace/<workspace_subdir>` as read-write bind mounts (docker) or `LocalDir`/`File` manifest entries (remote backends); `.git`/`.agents`/`.codex` are read-only (`_PROTECTED_METADATA_NAMES`); `--workspace-file` extras are read-only binds; `_extra_file_rel_path` rejects traversal/control chars. **Files out:** findings never leave through the sandbox — reporting/notes/coverage run host-side; screenshots go to `/workspace/.agent-browser-screenshots` and return as image blocks via `view_image`.

**Image (`containers/Dockerfile`):** Kali rolling, two stages (Go builder compiles `httpx`, `katana`, `vulnx`, `gospider`, `interactsh-client`, `govulncheck`). User `pentester` with `NOPASSWD` sudo. Notable tools: nmap (`setcap cap_net_raw,cap_net_admin,cap_net_bind_service`), sqlmap, nuclei, subfinder, naabu, ffuf, arjun, dirsearch, semgrep, bandit, wapiti, retire, `@ast-grep/cli`, tree-sitter parsers, trufflehog `3.95.9`, gitleaks, trivy, jwt_tool, `agent-browser@0.26.0` + chromium, Caido CLI `0.56.0`. Ships a generated test CA (`/app/certs/ca.{key,crt,p12}`) and `/app/.venv` (requests, httpx, bs4, lxml, pyjwt, cryptography, `caido-sdk-client`); `strix/tools/proxy/caido_api.py` is copied to `/opt/strix-python` with `PYTHONPATH` set, so host tools and sandbox scripts share one API.

**Proxy sidecar:** `docker-entrypoint.sh` runs `caido-cli --listen 0.0.0.0:48080 --allow-guests --no-logging --no-open --import-ca-cert /app/certs/ca.p12`; the host resolves it with `session.resolve_exposed_port(48080)` (`_CONTAINER_CAIDO_PORT = 48080`). Container env sets `http_proxy`/`https_proxy`/`ALL_PROXY=http://127.0.0.1:48080` (`NO_PROXY=localhost,127.0.0.1`); the entrypoint also writes `/etc/profile.d/proxy.sh`, `/etc/environment`, `/etc/wgetrc` and installs the CA into chromium's NSS db. `StrixDockerSandboxClient` subclasses the SDK client to (1) keep the image ENTRYPOINT (`command=["tail","-f","/dev/null"]`), (2) add `NET_ADMIN`/`NET_RAW` for `nmap -sS` (plus `SYS_ADMIN`, `/dev/fuse`, `apparmor:unconfined` when the manifest needs FUSE), (3) add `host.docker.internal` → host-gateway (localhost targets are rewritten to it). Resource caps are opt-in (`STRIX_SANDBOX_MEM_LIMIT`, `_SHM_SIZE`, `_CPUS`, `_PIDS_LIMIT`); log rotation defaults to 50m × 3; `STRIX_DOCKER_SANDBOX_NETWORK` switches networks and drops published ports (default is the plain bridge).

## 3. Tool inventory

`_BASE_TOOLS` (`factory.py:561-602`), all `@function_tool`: `think`; `load_skill`; todos `create_todo, list_todos, update_todo, mark_todo_done, mark_todo_pending, delete_todo`; notes `create_note, list_notes, get_note, update_note, delete_note`; coverage `record_coverage, update_coverage, list_coverage`; threat model `get_threat_model, save_threat_model, amend_threat_model`; `web_search, web_get_contents`; reporting `create_vulnerability_report, create_dependency_report, update_vulnerability_report, list_reports, get_report`; proxy `list_requests, view_request, repeat_request, list_sitemap, view_sitemap_entry, scope_rules`; MCP `list_mcps, describe_mcp, call_mcp`; graph `view_agent_graph, send_message_to_agent, wait_for_agents, create_agent, stop_agent`; lifecycle `finish_scan` (root) / `agent_finish` (child); `respond_to_user` (interactive). SDK-capability tools: `exec_command`, `write_stdin`, `patch`, `view_image`, plus filesystem read/write. Extend with `register_agent_tools(*tools)` or `strix.runtime.backends.register_backend`.

- **HTTP proxy interception:** Caido via the six `proxy` tools — `list_requests(httpql_filter, first=50, after, sort_by, sort_order, scope_id)` with cursor pagination (`page_info.end_cursor`) — plus `from caido_api import ...` in sandbox Python. `scope_rules` actions are `get|list|create|update|delete` (empty allowlist = allow-all; denylist wins); host-side Caido calls serialize behind `_CAIDO_CALL_LOCK`. HTTPQL rules are embedded in docstrings: no `NOT` operator (use `ne`/`ncont`/`nregex`), strings quoted, integers unquoted.
- **Browser automation:** no function tool; `agent-browser@0.26.0` driven through `exec_command`, one shared session unless `--session <agent-name>`, `AGENT_BROWSER_IDLE_TIMEOUT_MS=180000`, screenshots read back with `view_image`.
- **PoC/exploit scripting:** no dedicated python tool — scripts are written to `/workspace` and run as `python3 script.py` via `exec_command`, with `repeat_request`/`requests`/`httpx` for payload spraying. (An earlier release had native `strix/tools/{terminal,python,browser,file_edit}/*_schema.xml` modules; `main` replaced them with SDK capabilities + CLI.)

## 4. Validation / anti-false-positive discipline

Code-enforced gates in `create_vulnerability_report` (`strix/tools/reporting/tool.py`): `_REQUIRED_FIELDS` rejects blank `title, description, impact, target, technical_analysis, poc_description, poc_script_code` ("PoC script/code is REQUIRED — provide the actual exploit/payload"), `remediation_steps, evidence, assumptions`; `_validate_cvss_breakdown` requires all 8 `_CVSS_VALID` metrics, scored by `_calculate_cvss`; `confidence ∈ {high, medium, low}` with a mandatory `confidence_rationale` unless `high`; non-empty `counterevidence` and `severity_change_conditions`; `fix_effort ∈ {trivial, low, medium, high}`; `fix_verification` required (4-part closure/bypass/behavior/evidence statement) whenever a `code_location` carries `fix_after`; `code_locations` must be relative paths with `start_line ≥ 1 ≤ end_line`. `http_exchange_ids` (≤10 numeric ids, ≤128 chars) are checked against the live Caido project by `_verify_http_exchange_ids` — unknown ids are **rejected**; if the proxy is unreachable they are dropped with a warning rather than stored unverified. The docstring forbids filing suspicions/recon artifacts and "to be safe" CVSS inflation.

Dedup is an LLM judge: `strix/report/dedupe.py::check_duplicate` + `DEDUPE_SYSTEM_PROMPT` (same root cause + same component + same fix ⇒ duplicate; different endpoint/parameter/root cause ⇒ not), model via `STRIX_DEDUPE_MODEL`; dependency findings short-circuit on CVE+package+ecosystem (`_check_dependency_duplicate`), where a distinct `manifest_path` means a distinct finding. It **fails open** (exception ⇒ `is_duplicate: False`).

Negative space is tracked: `VALID_OUTCOMES = ("reported","no_issue_found","ruled_out","not_applicable","needs_follow_up")`, with `_OUTCOMES_REQUIRING_EVIDENCE = {"ruled_out","not_applicable","needs_follow_up"}`; `finish_scan` returns coverage counts, unresolved rows, and `skill_coverage_gaps` (risk classes an agent was equipped for but never accounted for). No separate reviewer agent exists — the root orchestrator reviews through root-only `list_reports`/`get_report`.

## 5. State / memory

Host-side singleton `ReportState` (`strix/report/state.py`); artifacts in `./strix_runs/<run-name>/`: `penetration_test_report.md`, `vulnerabilities/<vuln-NNNN>.md`, `vulnerabilities.json`, `vulnerabilities.csv`, `findings.sarif` (SARIF 2.1.0 + `versionControlProvenance` when exactly one repo target), `coverage.json`, `events.jsonl`, `run.json` (`strix/core/paths.py`: `RUNS_DIR_NAME`, `RUNTIME_STATE_DIR_NAME=".state"`, `RUN_RECORD_FILENAME`). `.state/` holds `agents.json` (graph snapshot) and `agents.db` (SDK `agents.memory.SQLiteSession`), both required by `--resume RUN_NAME`, plus `coverage.json` and hydrate-on-resume stores for todos, notes, threat models. The `create_note` docstring still claims notes are "in-memory only", contradicting `hydrate_notes_from_disk`. Notes are scan-shared; todos are keyed by `agent_id`; both record authorship. Ids are `vuln-%04d`; revisions keep the id, append `update_history`, and drop now-contradictory dependents (`_DEPENDENT_REPORT_FIELDS`). Context: `ContextSettings` (`compact_buffer_tokens=20_000`, `keep_tokens=8_000`, `fallback_context_tokens=200_000`, `summary_max_tokens=4_096`, `tool_output_max_tokens=8_000`/`lines=2_000`/`bytes=50KiB`), `strix/llm/{compaction,context_budget}.py`, `TurnToolCallLimiter` (`LLM_MAX_TOOL_CALLS_PER_TURN=32`), image budget (`STRIX_MAX_CONTEXT_IMAGES=3`).

## 6. Prompting

`strix/agents/prompts/system_prompt.jinja` (48.7 KB, 548 lines) is XML-tag structured: `<root_agent_directive>` (if `is_root`), `<core_capabilities>`, `<communication_rules>`, `<execution_guidelines>` (scope block from `system_prompt_context.authorized_targets`, MCP block), `<vulnerability_focus>` (ten targets: IDOR, SQLi, SSRF, XSS, XXE, RCE, CSRF, Race/TOCTOU, Business Logic, Auth/JWT), `<multi_agent_system>`, `<environment>`, `<specialized_knowledge>`, `<available_skills>`. Only `is_root`, `interactive`, and the context/skill dicts are conditional — `is_whitebox`, `scan_mode`, `is_diff_scoped` appear nowhere in the template; they only select which skill markdown is inlined by `prompt.py::_resolve_skills` (caller skills → `scan_modes/<mode>` → `scan_modes/diff` → `tooling/agent_browser` → `tooling/python` → `analysis/counterevidence` → `analysis/severity_calibration` → `coordination/root_agent` → the whitebox set). Skills are inlined and re-exposed through `env.globals["get_skill"]`; autoescape is off; on any exception `render_system_prompt` returns `""`.

Techniques worth copying: root is barred from hands-on testing ("Even a single quick test on a discovered endpoint is out of role"); a layered authority block (injected scope is authoritative, "FULL AUTHORIZATION", "NEVER wait for approval", prescribed vocabulary "validate, verify, reproduce, confirm"); anti-fingerprinting ("NEVER use any identifiable names/markers in HTTP requests, payloads, user-agents"); closure vocabulary (`confirmed`/`ruled_out`/`open_proof_gap`); a mandatory attack-chaining gate before finishing; "the agent after you sees your state, not your reasoning". Destructive-action and PoC-file-saving instructions are **absent** (zero hits for "destructive", "denial of service", `strix_runs`, `save_poc`).

## 7. CLI / UX

Entrypoint `strix = "strix.interface.main:main"`. Subcommands: `strix view`, `strix auth login chatgpt|status|logout` (`_CALLBACK_TIMEOUT_S=300`), `strix completions <zsh|bash|fish>`, `strix cloud <resource> <verb>` (exit 0/1/2/4/5). Scan flags: `-t/--target` (URL, repo, dir, domain, IP, API spec, `postman://<uuid>`; repeatable), `--target-list`, `--instruction`, `--instruction-file`, `--workspace-file PATH[:DEST]`, `-n/--non-interactive`, `-m/--scan-mode {quick,standard,deep}` (default `deep`; `diff` is an overlay, not a mode), `--scope-mode {auto,diff,full}`, `--diff-base`, `--config` (`~/.strix/cli-config.json`), `--mcp-config`, `--mcp-server`, `--mcp-exclude`, `--max-budget/--max-budget-usd`, `--max-turns` (default 500), `--resume RUN_NAME`, `-v/--version`, `--update`. `--scope-mode auto` enables diff scoping only when non-interactive **and** a CI env var (`CI`, `GITHUB_ACTIONS`, `GITLAB_CI`, `JENKINS_URL`, `BUILDKITE`, `CIRCLECI`) **and** a PR/base-branch signal is present. Headless exit codes: `0` clean, `1` fatal, `2` vulnerabilities found. `strix view` serves a prebuilt React SPA on `127.0.0.1` at an ephemeral port, gated by `secrets.token_urlsafe(32)` exchanged for a `strix_viewer_session_<port>` HttpOnly/SameSite=Strict cookie; GET `/api/{runs,run,vulnerabilities,report,transcript}`, POST `/api/{report/send,feedback,agents/steer}` (steer cap 4000), 403 without session, 401 for non-launch runs unless email-verified, ~1 s browser polling (no SSE); `/api/report/send` builds a locally encrypted PDF (`report_pdf.py::build_encrypted_report` → `strix-report-<run>.pdf`, relayed via `STRIX_APP_URL`). Interactive mode uses a Go/Bubble Tea TUI sidecar (`strix/bin/strix-tui`). `docs/tools/{browser,overview}.mdx` claim "Playwright-powered Chrome" and `sandbox.mdx` advertises ZAP — the image has `agent-browser`+Chromium and no ZAP (doc drift).

## 8. Code-level details worth copying

- Budget discipline (`strix/core/hooks.py`): `BudgetExceededError`, `SubagentBudgetReservedError`, `BudgetPausedError`; `_SUBAGENT_BUDGET_RESERVE = 0.90` stops children at 90% so root can still write the report; warn bands `(0.70, 0.85, 0.95)` root / `(0.75, 0.80, 0.85)` sub-agent with `<NOTICE|URGENT|CRITICAL>` wrap-up directives injected as model input; `DEFAULT_MAX_TURNS = 500`; `LLM_TIMEOUT = 300`, `LLM_STREAM_IDLE_TIMEOUT = 300`, `STRIX_REASONING_EFFORT = "high"`.
- Resilience: `_MAX_TRANSIENT_MODEL_RETRIES = 5` (90 s retry ceiling), `_MAX_COMPACTIONS_PER_CYCLE = 2`, `_WAITING_AUTO_RESUME_TIMEOUT_S = 300.0` with `_MAX_IDLE_AUTO_RESUMES = 3` (a wedged agent cannot buy fresh nudge budget by auto-resuming), `load_skill` timeout 10 s.
- `factory.py` pragmatics: `_with_bounded_result` (head/tail truncation + spill store), `_with_coerced_arguments` (fixes models emitting `"null"`/JSON strings for list/dict params), `_with_strictness`, `_function_tool_with_error_result` (tool exceptions become model-visible text), `_wrap_exec_command`, `_ensure_unique_tool_names`.

## 9. License and stated principles

**Apache-2.0** (`LICENSE`; GitHub API `spdx_id: apache-2.0`). Principles: PoC-validated findings over static-analysis false positives; platform-injected scope is authoritative and user text "do NOT expand scope"; "un-reported findings are not tracked and not credited"; authorized-use-only warnings in README and `docs/index.mdx`; final reports must not leak internal identifiers (proxy request ids, report ids, `/workspace` paths, agent names).

## 10. Missing / weak

1. **No per-agent isolation** — one container, one `/workspace`, passwordless sudo and `NET_ADMIN`/`NET_RAW` for every agent; peers share state, and scope is prompt text plus agent-managed `scope_rules`, so nothing blocks out-of-scope egress at the kernel level.
2. **Resource limits opt-in** (unbounded memory/CPU/PIDs by default); no egress allowlist.
3. **Doc drift**: "Playwright-powered Chrome"/ZAP/"Python Runtime" claims, `create_note` "in-memory only", the `openai-agents==0.14.6` pin, and four env vars documented but absent from code (`STRIX_LLM_MAX_RETRIES`, `STRIX_MEMORY_COMPRESSOR_TIMEOUT`, `STRIX_SANDBOX_EXECUTION_TIMEOUT`, `STRIX_SANDBOX_CONNECT_TIMEOUT`).
4. **Dedupe fails open** and accepts any judge `confidence` (no threshold).
5. **Prompt fragility**: `render_system_prompt` returns `""` on error with only a log; "3 agents per vulnerability" and "NO FLAT STRUCTURES" are unenforced prose.
6. **No CI test workflow** — `.github/workflows/` has only `build-release.yml`; 23k LOC of tests run only through local `make check-all`/pre-commit.
7. **Telemetry on by default** (`STRIX_TELEMETRY=True`; PostHog + Scarf + OTEL).
8. **Evidence linkage is best-effort** — `http_exchange_ids` are dropped (with a warning) whenever Caido is unreachable.
9. **PoC gate is absolute**: every dynamic finding needs `poc_script_code`, and the only non-dynamic `finding_class` is `dependency_cve` — no static/code-review class exists, pressuring white-box agents to manufacture PoCs.
10. Benchmarks live out of repo (`usestrix/benchmarks`; XBEN 104 challenges, 96% at v0.4.0); **unverified** whether the newer architecture still scores that.
