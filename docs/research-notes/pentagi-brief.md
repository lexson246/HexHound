## 1. Agent types & orchestration

**Exactly 13 LLM-configurable agent types** (`backend/pkg/providers/pconfig/config.go`, `ProviderOptionsType` / `AllAgentTypes`): `simple`, `simple_json`, `primary_agent`, `assistant`, `generator`, `refiner`, `adviser`, `reflector`, `searcher`, `enricher`, `coder`, `installer`, `pentester`. There is **no** `memorist`/`planner`/`reporter`/`execution_monitor`/`summarizer` config slot — roles map onto types (verified in `performers.go` / `performer.go`):

| Performer | optAgentType | msgChainType |
|---|---|---|
| reporter, summarizer, title/lang/image choosers | `simple` | `reporter` / `summarizer` |
| tool-call fixer | `simple_json` | `tool_call_fixer` |
| **memorist** | **`searcher`** | `memorist` |
| planner / mentor (execution monitor) | `adviser` + `question_task_planner.tmpl` / `question_execution_monitor.tmpl` | `adviser` |
| generator/refiner/coder/installer/pentester/reflector/enricher/primary/assistant | own type | own chain |

**Hierarchy**: Flow → Task → Subtask; workers `FlowController/FlowWorker`, `TaskController/TaskWorker`, `SubtaskController/SubtaskWorker`, `AssistantWorker` (`backend/pkg/controller/`). `SubtaskController{LoadSubtasks, GenerateSubtasks, RefineSubtasks, PopSubtask}`.

**Delegation is nested chains, not processes**: `coder`, `pentester`, `maintenance`(installer), `search`(searcher), `advice`(adviser), `memorist` are `tools.ExecutorHandler` closures that render the specialist prompt and synchronously run a *nested* `performAgentChain` with its own message chain. Context flows via `tools.PutAgentContext/GetAgentContext` → `{ParentAgentType, CurrentAgentType}`; every delegation writes an agent-log row via `putAgentLog(initiator, executor, …)`. Per-agent handler sets are pinned in `tools.<X>ExecutorConfig` (e.g. Primary = Adviser/Coder/Installer/Memorist/Pentester/Searcher/Barrier/Summarizer).

**Task decomposition**: Generator agent returns the whole list through the `subtask_list` tool (cap `TasksNumberLimit = 15`); after each subtask the Refiner returns a **delta** through `subtask_patch` (`SubtaskOpAdd/Remove/Modify/Reorder`). `fixSubtaskPatch` sanitizes LLM output (drops adds without title+description, drops ops on unknown IDs, **converts MODIFY with unknown ID into ADD**); `applySubtaskOperations` is two-pass (removes/modifies, then inserts/reorders); `calculateInsertIndex`: `AfterID` nil/0 → position 0 (beginning), known → `idx+1`, unknown → append. New subtasks carry `ID=0`; the TaskWorker recreates DB rows.

**Barriers**: `done` (Go constant `tools.FinalyToolName` — upstream misspelling) and `ask` (`ASK_USER`, default false). `PerformResult` enum: `PerformResultError/Waiting/Done`. `Done{Success,Result}` → `UpdateSubtaskResult` + a `MsglogTypeReport` row.

**Per-agent tool sets** (verified in `backend/pkg/tools/tools.go`, not just the handler lists): the **primary agent has no `terminal`/`file`/`browser` at all** — it is a pure delegation orchestrator with `done` + `advice` + `coder` + `maintenance` + `memorist` + `pentester` + `search` (plus `ask` iff `ASK_USER`). The **assistant has an empty barrier set** (no `done`/`ask`) and gets `terminal`, `file`, `browser`, `web_search`, the flow-manager tools, and either the delegation tools (`UseAgents=true`, default **false**) or the direct memory tools. `installer`/`coder`/`pentester` = `terminal` + `file` + their `*_result` barrier + delegations; `generator`/`refiner` = `terminal`,`file`,`memorist`,`search` + `subtask_list`/`subtask_patch`; `memorist`/`enricher` = `terminal`,`file`,`*_result`; `reporter` = `report_result` only; the **adviser has no executor at all** (runs via `performSimpleChain`). 42 tool constants total, of which 8 legacy per-engine search tools are defined but never wired.

**Resume mechanics**: `FlowController.LoadFlows` → `LoadFlowWorker` loads only flows in `running|waiting` (else `ErrNothingToLoad`), reloading container image, language, title and `ToolCallIDTemplate` from the DB, rebuilding the executor + 8 log workers, then `LoadTasks`/`LoadAssistantWorker`. The reloaded worker re-runs each loaded task with the literal input **`"continue after loading"`**. `LoadSubtaskWorker` maps `running`→re-created (**restarts from scratch**), `waiting`→resumable, `created`→`ErrNothingToLoad`.

**Persistence/resume**: the chain is `[]llms.MessageContent` (langchaingo) JSON-marshalled into `msgchains.chain` (`json.RawMessage`) — no message table — rewritten after every AI message, tool response and summarization (`UpdateMsgChain`); usage is a separate `UpdateMsgChainUsage`. Resume: `restoreChain()` → `GetFlowTaskTypeLastMsgChain` → `cast.NewChainAST(chain, true)` → overwrite system message, drop trailing unanswered `RequestResponse` pair, `AppendHumanMessage` → `NormalizeToolCallIDs(tcIDTemplate)` → `SanitizeToolCallArguments()` → `ClearReasoning()` → restore-specific summarizer → **`CreateMsgChain` (append-only new row)**. `EnsureChainConsistency` fills unresponded tool calls with `cast.FallbackResponseContent`; a provider/model switch appends `ChainContinuationMessage = "Continue from where we left off"`.

**Framework**: a **fork** — `github.com/vxcontrol/langchaingo` (not `tmc/`), v0.1.14-update.6; subpackages `llms`, `llms/reasoning`, `llms/streaming`, `llms/openai`. Tools wired via `Provider.CallWithTools(ctx, opt, chain, executor.Tools(), streamCb)`; schemas from `executor.GetToolSchema(name)`. Two file names that mislead: **`provider/wrapper.go` is the Langfuse instrumentation wrapper** (`WrapGenerateFromSinglePrompt`/`WrapGenerateContent`), not the provider implementation, and **`litellm.go` is just a `/models` list loader**. GraphQL subscriptions push 10 event types to the UI.

## 2. Memory architecture

**pgvector via langchaingo's pgvector store; collection name is literally `"langchain"`** (`pgvector.WithCollectionName("langchain")`, `pkg/tools/tools.go`). Tables `langchain_pg_collection(name, cmetadata, uuid)` and `langchain_pg_embedding(collection_id, embedding vector, document, cmetadata, uuid)`, created in `backend/migrations/sql/20260501_120000_knowledge.sql` (comment: DDL kept identical to langchaingo's). The `embedding` column has **no typmod and there is NO ANN index** — grepping all 31 migrations finds only the btree FK index `langchain_pg_embedding_collection_id`, and the langchaingo fork only emits HNSW when `WithHNSWIndex` / `vector(N)` when `WithVectorDimensions` are passed, which PentAGI passes neither of ⇒ **every similarity search is an exact sequential scan** (`docs/database.md:427` states this too). Embeddings: `EMBEDDING_PROVIDER` defaults to `openai` (per-provider default models: `text-embedding-ada-002`, `mistral-embed`, `jina-embeddings-v2-small-en`, `BAAI/bge-small-en-v1.5`, `embedding-001`, `voyage-4`), `EMBEDDING_MAX_TEXT_BYTES=8192`, `EMBEDDING_BATCH_SIZE=512` in code (the README says 100 — code wins). Store API actually used: `SimilaritySearch(ctx, q, 3, WithScoreThreshold(0.2), WithFilters(...))`, `AddDocuments`, `Close`; over-length text is embedded as `text[:8192]` but the **full text is stored**.

**Four doc types**: `memory` (`memoryVectorStoreDefaultType`), `guide`, `answer` (`searchVectorStoreDefaultType`), `code`. Metadata: `flow_id`, `doc_type`, `task_id`, `subtask_id`, `tool_name`/`tool_description`/`part_size`/`total_size`, plus `guide_type` / `answer_type` / `code_lang`.

**Retrieval**: one fixed setting for all four stores — **threshold `0.2`, top-k `3`, not configurable**. Tools `search_in_memory` (1–5 natural-language queries, results merged+deduped+ranked), `search_guide`/`store_guide`, `search_answer`/`store_answer`, `search_code`/`store_code`. Result blocks are formatted `"Retrieved Memory Fact %d Match score: %f"`; misses return instructive strings (e.g. `"nothing found in answer store and you need to store it after figure out this case"`).

**Post-processing is a `MergeAndDeduplicateDocs` pass** — SHA-256 dedupe, keep max score, sort descending, cap 3; there is no chain-AST "decompression" of retrieved memory. **Auto-store**: `allowedStoringInMemoryTools` (18 tools: terminal, file, all search engines, agent tools) auto-persist results as `doc_type=memory`, chunked **2000 chars / 100 overlap**. Only `allowedSummarizingToolsResult = {terminal, browser}` get LLM summarization (see §3). A DB layer on top adds 14 sqlc queries (`InsertKnowledgeDocument`, `SearchKnowledgeDocuments`, `SearchUserKnowledgeDocuments`, List/Get/Update/Delete) that hardcode the `langchain` collection, use cosine `<=>` with `max_distance = 1 - threshold = 0.8`, and exclude `doc_type='memory'` from knowledge views.

**Knowledge graph (optional)**: Graphiti + Neo4j (`GRAPHITI_ENABLED=false` default, `GRAPHITI_URL`, `NEO4J_URI=bolt://neo4j:7687`, `GRAPHITI_SEARCH_SCOPE=flowid`). Tool `graphiti_search` offers 7 search types (`temporal_window`, `entity_relationships`, `diverse_results`, `episode_context`, `successful_tools`, `recent_context`, `entity_by_label`) and is registered **only for coder, pentester, memorist, enricher**. Degrades gracefully ("Graphiti knowledge graph is not enabled…"). Ingestion policy `GRAPHITI_INGEST_POLICY_RULES` with `REJECT|PROCESS|SKIP_LLM`; taxonomy layers `STRUCTURAL,EVIDENCE,PROGRESS,ATTEMPT`. Client internals: health check 3 attempts × 2 s, after which the client stays disabled for the process lifetime; graphs are namespaced by `GroupID(flowID)`; per-search-type result defaults 15/10/15/10/20/10/25 with `max_depth ≤ 3`, `min_mentions=2`, diversity `low|medium|high` and recency windows `1h|6h|24h|7d`; when disabled the tool is simply not registered, transport/5xx errors degrade softly (nil error) while 4xx hard-fails with a 512-byte-capped message. Node labels are PascalCase singular, edge types UPPER_SNAKE_CASE.

## 3. Tool execution

**One persistent container per flow** — no tmux, no per-task container. Name `pentagi-terminal-<flowID>`, entrypoint `tail -f /dev/null`; commands run via Docker `ExecCreate` with `sh -c <cmd>`, `TTY: true`, `WorkingDir=/work`, stdout via `ExecAttach`+`io.Copy`; `detach=true` → background exec with a 500 ms quick-check.

- Constants (`pkg/docker/client.go`): `WorkFolderPathInContainer="/work"`, `defaultImage="debian:latest"`, `BaseContainerPortsNumber=28000`, `containerPortsNumber=2`, `limitContainerPortsNumber=2000`, `containerListWorkers=20`, `maxListEntries=10000`, `containerStartupGrace=1500ms`. Ports per flow: `portsBase + (flowID*2 + i) % 2000`.
- Binds: `<DOCKER_WORK_DIR | named volume <name>-data>:/work`; `/var/run/docker.sock` **only if `DOCKER_INSIDE=true`** (documented host-escape risk, issue #337). CapDrop ALL + explicit allow-list (default set minus MKNOD, plus SYS_PTRACE, plus NET_ADMIN when `DOCKER_NET_ADMIN=true`); `PidsLimit=2048`; restart `on-failure/5`.
- Image chosen by an LLM call (`image_chooser.tmpl`, `{{.DefaultImageForPentest}}`); fallbacks `DOCKER_DEFAULT_IMAGE` and `pentestDockerImage = "vxcontrol/kali-linux"`.
- Terminal timeout: `TERMINAL_TOOL_TIMEOUT` default **1200 s**, hard cap `maxExplicitExecCommandTimeout` **3 h**.

**Output governing** (`pkg/tools/executor.go`): `DefaultResultSizeLimit = 16*1024`; if tool ∈ {terminal, browser} and result > 16 KB → **LLM summarization** (target ≤ 8 KB = limit/2); else if > 32 KB → head 16 KB + `[0:16384 bytes] ... [truncated] ... [16384:N bytes]` + tail 16 KB. Argument values truncated at `maxArgValueLength = 1024`.

**Tool surface** (`pkg/tools/registry.go`): environment (`terminal`, `file`); assistant-only flow control (`get_flow_status`, `stop_flow`, `submit_flow_input`, `patch_flow_subtasks`, `wait_flow_completion`); search (`browser`, `web_search`, plus legacy `google/duckduckgo/tavily/firecrawl/traversaal/perplexity/searxng/sploitus`); vector DB (8 tools); agent delegation; store-result; barrier. `web_search` takes `mode ∈ links|answer|research|exploit`; the per-mode fallback ladder is a data table in `pkg/tools/web_search.go`, primitives in `pkg/tools/searchers/` (typed errors `Retryable|Fatal|ErrNotConfigured`), `maxEngineAttempts=2`. `browser` returns markdown/HTML/links and auto-captures screenshots; scraping runs in a **separate scraper container** (`SCRAPER_PRIVATE_URL`/`PUBLIC`, `LOCAL_SCRAPER_MAX_CONCURRENT_SESSIONS=10`), chosen by whether the target IP is private.

## 4. Prompt engineering

Registry: `backend/pkg/templates/templates.go`; files `backend/pkg/templates/prompts/*.tmpl`: agent prompts (`primary_agent`, `assistant`, `pentester`, `coder`, `installer`, `searcher`, `enricher`, `memorist`, `adviser`, `generator`, `refiner`, `reflector`, `reporter`, `summarizer`), `question_*` variants per agent, and utilities (`flow_descriptor`, `task_descriptor`, `image_chooser`, `language_chooser`, `toolcall_fixer`, `input_toolcall_fixer`, `tool_call_id_collector/detector`, `execution_logs`, `full/short_execution_context`, `subtasks_generator/refiner`, `task_reporter`, `task_assignment_wrapper`).

Techniques (from `backend/docs/prompt_engineering_pentagi.md` + templates):
- **XML semantic delimiters**, consistent across prompts: `<container_constraints>`, `<terminal_protocol>`, `<tool_usage_rules>`, `<memory_protocol>`, `<team_specialists>`, `<delegation_rules>`, `<summarized_content_handling>`, `<engagement_scope>`.
- **Memory-first rule**: retrieve from vector memory *before* external actions.
- **Action economy**: searcher limited to 3–5 search actions, stop as soon as sufficient.
- **Mandatory final tool** per agent: `hack_result` (pentester), `code_result` (coder), `maintenance_result` (installer), `search_result` (searcher), `memorist_result`, `report_result` (reporter), `done` (orchestrator). All actions must be structured tool calls; simulating actions in text is explicitly forbidden.
- `{{.ToolPlaceholder}}` (`"Execute operations via function invocation - textual responses are not acceptable for task completion."`) is appended at the **very end** of every prompt.
- **Summarization-awareness protocol** must appear verbatim in all agent prompts: never mimic summary formats, never emit `{{.SummarizedContentPrefix}}`, never call `{{.SummarizationToolName}}`.
- ALL-CAPS prohibitions; delegation must carry complete context; prompts end with a numbered `## COMPLETION REQUIREMENTS` list; `{{.ExecutionContext}}`, `{{.Lang}}`, `{{.DockerImage}}`, `{{.Cwd}}`, `{{.ContainerPorts}}` + 50 more variables.
- **Registry mechanics**: 39 `PromptType` consts ↔ 39 files, each const string == filename minus `.tmpl` (irregular: `PromptTypeToolCallFixer="toolcall_fixer"`, `PromptTypeInputToolCallFixer="input_toolcall_fixer"`), registered by `//go:embed prompts/*.tmpl` + `ReadDir` + `TrimSuffix`. Every prompt is **user-overridable at runtime** via per-user rows in the `prompts` table, overlaid by `newUserPrompter` (`controller/prompter.go`) and validated by `validator.ValidatePrompt` (error types `Empty Template`, `Syntax Error`, `Unauthorized Variable`, `Rendering Failed`; `PromptVariables` is a whitelist, not a required set).
- **Verbatim rules worth stealing**: dual-channel language policy ("External search engines and the vector store are indexed in English … any non-English query retrieves nothing", `assistant.tmpl:31`); "ALWAYS search Graphiti FIRST" (`pentester.tmpl:39`); "Limit yourself to 3-5 search actions maximum" (`searcher.tmpl:42`); "Maximum 2 installation attempts before proposing alternatives" (`installer.tmpl:88`); "Hallucinated flags: verify uncertain syntax with `[tool] -h`" (`pentester.tmpl:334`); "Maximum 3 attempts of identical tool calls".
- **Notably absent from every prompt**: no template asks an agent to write a report to a file, and none requires CVSS/CVE/severity output.
- **Adviser/mentor**: when `EXECUTION_MONITOR_ENABLED=true` (same-tool limit 5, total limit 10) the adviser is invoked as mentor and the tool response is wrapped `<original_result>` + `<mentor_analysis>`. **Planner**: `AGENT_PLANNING_STEP_ENABLED=true` → adviser in planning mode emits 3–7 steps injected as `<task_assignment><original_request>/<execution_plan>/<hint>`. **Reflector** fires when the model returns no tool call, after 3 failed call attempts, and near the iteration limit.

## 5. Reporting & findings

Reporter agent (`reporter.tmpl`, runs on `simple`) independently judges execution and **must** call `report_result` with `success` (bool), `result`, `message`; report ≤ `{{.N}}` chars, starts with an explicit SUCCESS/FAILURE verdict; language policy: report in `{{.Lang}}`, technical channel stays English, CVE/tool/IP identifiers preserved verbatim. `task_reporter.tmpl` provides the XML context (`user_task`, `completed_subtasks`, `planned_subtasks`, `execution_state`, `execution_logs`). The report is **a DB row, never a file**: `provider.go:856–875` writes a `MsglogTypeReport` row then `updateMsgLogResult(..., MsglogResultFormatMarkdown)`; results also land in `subtasks.result`. `msglogs` columns: `id, type, message, result, flow_id, task_id, subtask_id, created_at, result_format, thinking`; enums `MsglogType` = answer/report/thoughts/browser/terminal/file/search/advice/ask/input/done and `MsglogResultFormat` = plain/markdown/terminal. **The final flow report is assembled client-side**: `frontend/src/lib/report/report.ts:90 generateReport()` concatenates task/subtask input+result into Markdown, and PDF comes from `@react-pdf/renderer` (`report-pdf.tsx`, lazy-imported at `report.ts:203–207`). Exports are **Markdown + PDF + clipboard only**; the README confirms JSON flow-report export is unsupported. (`flow_files` is a privilege namespace, not a table.)

**No structured vulnerability model exists**: zero hits for a `Vulnerability` struct, severity enum, CVSS field or finding-level dedup anywhere in the downloaded Go sources / `pkg/database/models.go`; `CVSS` appears only as a field returned by the Sploitus search backend. Findings are free text inside reports. Dedup exists only in vector retrieval (merge/rank), not for findings.

## 6. Guardrails, observability, cost

- **No runtime scope enforcement.** `.env.example` and `config.go` contain no scope/allowlist/deny knob; the only "scope" keys are `GRAPHITI_SEARCH_SCOPE` and OAuth scope. Scope is **prompt-level only**: `examples/prompts/scope_of_work_pentest.md` defines `<engagement_scope>` (allowed_targets, out_of_scope_targets, allowed/forbidden_actions, rate_limits_and_windows, credentials, stop_conditions, evidence_expectations) plus an 8-step `<scope_check_protocol>` — and states *"This template is guidance only. It does not replace legal authorization, customer approval, or future backend validation."* The file then lists "Backend Validation Ideas" (unimplemented).
- **Hard limits**: `MAX_GENERAL_AGENT_TOOL_CALLS=100` (assistant, primary, pentester, coder, installer) vs `MAX_LIMITED_AGENT_TOOL_CALLS=20` (others); `RepeatingToolCallThreshold=3`; `maxRetriesToCallSimpleChain/AgentChain/Function = 3`; `maxReflectorCallsPerChain=3`; `maxAgentShutdownIterations=3` (reflector-guided graceful termination starts 3 iterations early); `delayBetweenRetries=5s`; `maxSoftDetectionsBeforeAbort=4`.
- **Auth/secret caveats worth knowing before copying**: API tokens are JWT HS256 with only a non-secret 10-char `token_id` persisted, but `auth_middleware.go:210–213` **disables token validation entirely when `COOKIE_SIGNING_SALT` is `""` or the literal `"salt"`** — which is exactly what `.env.example:174` ships; and `api_token_cache.go:76` appends `PrivilegeAutomation` to **every** token. Provider keys are plaintext env values, scrubbed from logs by 31 patterns from `config.go:434–489 GetSecretPatterns()` — but `obs.go:490–509` copies logrus fields verbatim into OTel spans, bypassing that scrub.
- **Two "safety" features are effectively decorative**: `newGuardrail` exists only as a Langfuse observation type with **zero production call sites** (grep-verified), and the anonymizer is a manual `POST /anonymize/text` endpoint (`services/anonymizer.go:44`, privilege `anonymize.call`) that nothing in the agent loop ever calls. The real guardrails are the per-chain tool-call caps, the execution monitor (which fires the adviser and does **not** block), the reflector, and Docker isolation. **There is no cost ceiling or budget field anywhere** in config.
- **Secrets/auth**: per-provider env keys, per-user provider rows in DB, Bearer API tokens, OAuth (Google/GitHub), session cookies, `COOKIE_SIGNING_SALT`.
- **Observability**: Langfuse (`LANGFUSE_BASE_URL/PUBLIC_KEY/SECRET_KEY`; agents/tools/retrievers instrumented via `pkg/observability/langfuse`) and OpenTelemetry → VictoriaMetrics/Loki/Jaeger/Grafana (`OTEL_HOST`, plus listen vars); `pkg/server/services/anonymizer.go` exists (contents unverified); postgres-exporter.
- **Rate limiting**: only per-engine retry/backoff inside `web_search` (429/5xx/transport, `maxEngineAttempts=2`) and the scraper session cap (10). No global agent rate limiter found (Redis in the compose stack belongs to Langfuse) — unverified beyond that.
- **Cost/token accounting is per agent**: `pconfig.CallUsage{Input,Output,CacheRead,CacheWrite,CostInput,CostOutput}` with `UpdateCost(price)` doing cache-aware math (`uncached*input + cacheRead*cacheRead + cacheWrite*cacheWrite`, per-1e6), persisted per chain in `msgchains` (`UsageIn/Out/CacheIn/CacheOut/CostIn/CostOut`, `DurationSeconds`).

## 7. Code-level details worth copying

- Layout: `backend/{cmd/{pentagi,ctester,etester,ftester,installer}, pkg/{config,server,graph,controller,database,providers,tools,docker,terminal,csum,graphiti,observability,flowfiles,templates}, migrations/sql}`; `frontend/` React+TS+Apollo; `observability/`. Helper binaries: `ctester` (provider/tool-calling conformance), `ftester` (agent function tests with mocks), `etester` (embeddings). Migrations run via goose; queries are SQLC-generated.
- **Chain summarization** (`pkg/csum`, docs `chain_summary.md`, `chain_ast.md`): `ChainAST` sections + body pairs; pipeline = needs-summarization check → section summarization → oversized body pairs → last-section size → QA summarization → rebuild **only if smaller**. Global defaults `SUMMARIZER_PRESERVE_LAST=true, USE_QA=true, SUM_MSG_HUMAN_IN_QA=false, LAST_SEC_BYTES=51200, MAX_BP_BYTES=16384, MAX_QA_SECTIONS=10, MAX_QA_BYTES=65536, KEEP_QA_SECTIONS=1`; assistant variant `76800/16384/7/76800/3`; restore-time `16KB/8KB/3/20KB/1`.
- **Summarizer cache**: `summarizerCacheMaxSize=100`, SHA-256 keyed, non-expirable LRU (`providers.go`) — the docs' "1000 entries, 4 h TTL" is wrong; code is authoritative (doc/code drift).
- **Tool-call-ID pattern detection** (`providers/provider/agents.go`): 5 parallel samples of a synthetic `get_number` tool call → AI detects a template such as `toolu_{r:24:b}` / `call_{r:24:x}` / `{f}:{r:1:d}` (charsets `d l u a h H x b`), validated by `templates.ValidatePattern`, with a char-by-char heuristic fallback; cached per provider type. Solves provider-specific `tool_call_id` formats (fork-specific — low portability).
- **Tool-call repair**: invalid JSON args are sanitized then replaced with `{}` and regenerated by a `simple_json` agent (`toolcall_fixer` + `input_toolcall_fixer` templates, schema in the prompt); failures wrapped as `ErrFlowStateGuard` skip the fixer.
- **Size-based prompt degradation**: generator shrinks the subtask list by halving while the rendered template ≥ `msgGeneratorSizeLimit` (150 KB); refiner escalates base → `+ExecutionState` → `+ExecutionLogs` at `msgRefinerSizeLimit` (100 KB); `msgReporterSizeLimit=100 KB`, `msgSummarizerLimit=32 KB`, `textTruncateMessage="\n\n[...truncated]"`.
- Other constants: `TasksNumberLimit=15`, `deltaCallCounter=10000`, `extractLastMessagesCount=30`, `extractToolCallsCount=10`, `toolCallsHistorySeparator="---------------TOOL_CALLS_HISTORY---------------"`, `flowOperationTimeout=15s`, `waitFlowDefaultTimeout=1m`/max `1h`, `taskReadyPollInterval=5s`/timeout `2m`, flow-manager truncations (`msgLogsLimit=16KB`, `summaryLimit=32KB`, `subtaskListLimit=48KB`, `resultLimit=8KB`, `summarizationLimit=128KB` hard), `msgLogResultSummarySizeLimit=70KB`, `msgLogResultEntrySizeLimit=1KB`.
- **The task loop tolerates overshoot**: `TaskWorker.Run` iterates `for len(ListSubtasks) < TasksNumberLimit+3 { PopSubtask → Run → RefineSubtasks }` — i.e. the generator's 15-subtask cap is soft, with 3 slots of slack for refinement. Repeat detection is two-tier: warn at `RepeatingToolCallThreshold=3` identical calls, **abort the chain at 7** (`3 + maxSoftDetectionsBeforeAbort=4`).
- **Defaults live in `backend/pkg/config/config.go` as `envDefault` struct tags** (`env:"MAX_GENERAL_AGENT_TOOL_CALLS" envDefault:"100"`), not in `.env.example`, which leaves them empty — config.go is the source of truth for every knob above.
- **Per-agent model defaults** (`providers/openai/config.yml`): `simple/simple_json/searcher/enricher` = `gpt-5.4-nano`; `primary_agent/assistant/reflector/installer/pentester` = `gpt-5.4-mini`; `generator/refiner/adviser/coder` = `gpt-5.6-terra`; `max_tokens` 4096–32768. Every tool-bearing reasoning agent sets `reasoning: {mode: off}` because `/v1/chat/completions` rejects function tools combined with default-on thinking (verified live via `ctester`). Anthropic: `claude-haiku-4-5` utility/reflector/searcher, `claude-sonnet-5` primary/coder/installer/pentester, `claude-opus-4-8` generator/refiner, adviser `effort: xhigh`.

## What is missing / weak (headroom for a simpler project)

1. **No scope enforcement in code** — prompt-only, and the repo itself files backend validation under "ideas". A blocked-attempt reminder is also unimplemented.
2. **No structured findings**: no vulnerability entity, severity enum, CVSS vector, evidence links, or finding dedup → no machine-readable output, no re-test diffing, no triage workflow.
3. **Fixed, non-tunable retrieval**: threshold 0.2 / top-3 hardcoded per store, no reranking, no ANN index confirmed, only 4 doc types.
4. **Operational weight**: PostgreSQL+pgvector, Neo4j, Graphiti, Langfuse (+ClickHouse/Redis/MinIO), VictoriaMetrics/Loki/Jaeger/Grafana, 11 provider adapters, ~750 backend files for what is often a single-operator tool.
5. **Coarse execution model**: one shared container per flow for all agents (no per-agent isolation, no per-task sandbox), exec-only against `tail -f /dev/null`, no session/tmux persistence, coarse `detach` semantics.
6. `DOCKER_INSIDE=true` is a self-documented host-escape vector (#337).
7. **Reporting is an unverified LLM verdict** ("SUCCESS/FAILURE" from the reporter) — no evidence chain or signed receipts (an `examples/proposals/evidence_chain.md` design exists, unshipped).
8. Documentation drift (summarizer cache 1000/4 h vs `100`/no TTL) — docs lag the code.

## Portable to a small single-process Python agent

- Drop the 13-role taxonomy: 1 orchestrator + 3–4 specialists (researcher, coder, pentester) as plain functions returning strings, not nested chains.
- **Copy the output governor verbatim** — 16 KB result cap → LLM-summarize noisy tools (terminal/browser) → head/tail truncate at 32 KB → 1 KB per-argument cap. Best effort/benefit ratio in the repo.
- Memory: one pgvector/SQLite-VSS table with `doc_type ∈ {guide, answer, code, memory}`, threshold 0.2, top-3, metadata filters (`flow_id`, `task_id`, `subtask_id`), and the "nothing found — store it after you figure out this case" miss prompts. Skip Neo4j; the graph adds little over the same table.
- Barrier tools `done`/`ask` + an explicit `PerformResult` enum + a mandatory final-result tool per specialist; reflector on "no tool call" (max 3) is cheap and effective.
- JSON-Schema tool args + automated repair (sanitize → `{}` → repair via schema) transfers directly; the tool-call-ID pattern detector does **not** (fork-specific).
- Persist each chain as one JSON blob, append-only new rows on resume, and append "Continue from where we left off" — trivially portable.
- Copy the supervision thresholds (same tool 5 / total 10, general 100 / limited 20) and a cheap mentor pass instead of a full planner; implement scope as a **code-level allowlist**, not a prompt.
